# Dashboard

React + TypeScript + Vite 网站基础骨架。代码托管于 [A-Kuan/Dashboard](https://github.com/A-Kuan/Dashboard)。

当前采用顶部主导航与模块二级导航，工作台首页读取真实客户、SKU 与报价模板数据，集中展示业务入口、客户进展、待补充资料和最近模板。客户、报价、商品和系统设置模块按各自工作流保留看板、双栏工作区、数据表格或分组列表结构，并统一为暖白表面、克莱因蓝主操作和细边框视觉系统。报价模板可搜索、新建、编辑和删除；可直接输入 SKU 编码，或打开 SKU 库抽屉搜索、多选已有 SKU。已有 SKU 会自动带出名称、品牌和售价，模板仍允许调整本次保存的价格快照。一次性报价草稿不持久保存，库存与适配信息仍需在报价时人工核对。

## 快速开始

使用 Node.js 24.16.0 和 npm 11.x。

```bash
git clone https://github.com/A-Kuan/Dashboard.git
cd Dashboard
npm ci
npm run dev
```

本地访问：http://127.0.0.1:4179。

## 已具备的基础

- React + TypeScript 严格模式、Vite 开发与构建。
- React Router 基础路由、共享布局入口、首页、独立报价模板路由与 404。
- SKU 报价模板支持手输编码或从现有 SKU 库批量添加，品牌、名称和价格可在表格内调整；报价草稿可复制文字。
- 配置驱动的顶部主导航与模块二级导航，支持功能入口搜索、账号菜单和手机端展开/收起；图标采用 Tabler Icons。
- 环境变量样例、精确依赖、依赖锁文件、统一格式与 lint。
- GitHub Actions：Linux / Windows 安装、格式、lint、类型和构建检查。
- 多环境协作说明，以及全局文档随相关改动同步更新的规则。

新增 Node.js + SQLite 后端：登录验证、管理员/编辑/只读角色、客户档案、汽配 SKU、报价模板与客户专属价格均已实现。SKU 支持供货性质、产地、件号、适配与库存库位。客户、SKU 和报价模板数据持久保存；报价模板尚未与客户和 SKU 档案自动联动。公网入口为 [https://121.41.24.42/](https://121.41.24.42/)，部署与备份见 [部署说明](docs/DEPLOYMENT.md)。

客户档案现以“客户项目”看板呈现：按待跟进、询价中、已报价、合作中分列，按同行、修理厂、待分类筛选。新增与编辑使用分区式客户档案，客户编号自动生成，可维护主联系人及多个其他联系人、联系方式、客户来源与负责人、主营品牌与标签、开票结算、地址和备注；资料均保存到 SQLite。右侧详情展示真实客户资料与跟进记录。报价记录尚未与客户项目关联，显示明确空状态。

报价现按客户类型取同行价或修理厂价；少数客户可维护协议价，并优先使用。SKU 可逐次记录供应商报价及日期，保留历史。SKU 列表选择客户后可打开快速报价，临时调整本次售价、查看与最近供应商报价的差额并复制报价文字。供应商报价只是参考，不等于实际到货成本或利润。

已从旧站导入 SKU、关联件号和适配车型；其中名称含“弃用零件”的 246 条已删除，当前保留 12,248 条 SKU。列表使用服务端分页和搜索。旧站未提供可确定对应的品牌、配件性质、产地和当前两档售价；导入时这些字段原为留空或待确认。随后按用户明确要求，现有全部 SKU 的品牌统一设为“保时捷原厂”，供货性质统一设为对应字典项 `porsche_genuine_original_pack`；原始来源记录仍保留供核对，其他缺失字段未推断。导入过程和备份方法见开发文档。

旧站字典已迁入并按实际功能清理；SKU 正在使用的 8 组商品基础字典在 `/sku-foundation` 查看和维护。配置中心在 `/settings/dictionaries` 维护客户类型与客户跟进阶段，供客户表单、筛选、看板分列和服务端校验统一使用。SKU 编辑器使用商品基础字典中的品类、商品品牌、基本单位、供货性质、安装位置、适配汽车品牌、经营状态和适配核实状态；安装位置可组合选择。供货性质按原厂件、品牌件、待核实及其子项选择，并保存字典编码。旧 SKU 的“待确认”等历史值继续允许编辑，不会批量改写；列表将“待确认”标为“待核实（旧值）”，可用“待核实”一起筛选。

首次打开页面，读取本机 `.data/setup-token.txt` 中的一次性初始化码，自行设置管理员账号和密码（必填，最多 128 位）。后续账号由管理员创建，无公开注册。正式数据库不预置虚构业务数据。

## 常用命令

```bash
npm run dev          # 本地开发
npm run check        # 格式、lint、后端集成测试、类型与构建
npm run format       # 自动统一格式
npm test             # 权限、数据校验与持久化集成测试
npm start            # 提供 dist 和 API，需先构建并配置 APP_ORIGIN
```
