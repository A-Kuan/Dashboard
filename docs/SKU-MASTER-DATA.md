# 虎山行 SKU 资料库 v2

## 产品定位

SKU 资料库不是库存表，也不是简单商品列表。它是虎山行的“汽配识别与适配中心”，负责回答四个问题：

1. 这是什么零件；
2. 它有哪些 OE、品牌号、历史号和替代关系；
3. 它能否准确适配指定车辆；
4. 结论来自哪里，是否已核验。

库存、采购价和销售价可以在详情中辅助判断，但不与零件身份混为一体。第一阶段只实现前端视觉与交互原型，使用独立模拟数据，不读取或写入旧业务接口。

## 核心用户与任务

- 销售：收到 OE、VIN、车型或零件名称后，快速定位可售 SKU，确认适配再报价。
- 采购：核对品牌号、替代关系和供应商资料，避免采购错件。
- 资料员：从 EPC、VIN、品牌目录或供应商文件建立资料，补齐证据并完成核验。
- 管理者：查看资料完整度、待核验量和变更记录，识别数据风险。

## 页面信息架构

### 列表首页

- 一个主搜索框：支持 SKU、OE、配件名称、品牌、车型。
- 状态切换：全部、已核验、待核验、草稿。
- 主列表：SKU/名称、主 OE、品牌/分类、适配数量、资料状态、更新时间。
- 右侧核验详情：编号关系、适配条件、来源证据、库存价格和变更记录。
- 新建 SKU：先选来源，再进入录入；默认推荐 EPC/VIN 来源。

列表与详情同屏，选择记录后详情即时更新，避免频繁跳页。正文保持 14–16px，零件名、SKU 与 OE 使用 16–20px 中高字重，不通过缩小字体压缩内容。

### 新建流程

1. 选择来源：EPC/VIN、OE 查询、批量导入、手工建立。
2. 保存原始证据：来源系统、目录、图组、位置、原始名称、VIN 条件、同步时间与原始记录标识。
3. 生成匹配预览：按规范 OE 匹配现有 SKU，按平台、版本、年款、发动机、变速箱和 PR 码解释车型候选。
4. 人工决定：逐条选择附加证据、建立草稿或跳过；歧义编号不自动写入。
5. 标准化与核验：补齐品牌、叶子分类和适配条件，再进入适配审核及资料审核。

## 数据规则

- SKU 编码创建后不可复用；停用使用生命周期状态，不物理删除。
- 所有零件号同时保存原始值与标准化值；搜索使用标准化值，显示保留原始格式。
- 替代关系有方向：`A 被 B 替代` 不等于双向等价。
- 适配必须保存具体条件；不得仅凭名称或单个 VIN 推断整个车型平台适配。
- `oem_reference` 是 EPC 来源参考价，只读；不得作为采购价、成本价或销售价保存。
- 供应商报价属于商业报价域，一个 SKU 可对应多个供应商件号和报价。
- 库存按仓库、库位和批次汇总；可用量、锁定量和在途量必须能追溯来源。
- 所有核验、发布和关键字段变更保留操作者、时间、版本与差异摘要。

## 页面状态

- `draft` 草稿：身份或来源尚不完整。
- `review` 待核验：已形成候选资料，但存在适配、编号或来源待确认项。
- `verified` 已核验：身份、主 OE、至少一个适配结论和来源证据均通过检查。
- `discontinued` 已停用：不再用于新业务，但历史单据和来源关系保留。

完整度是提示信息，不替代核验状态。建议权重：身份 25%、编号 20%、适配 30%、来源 20%、媒体 5%。

## v2 接口边界

后续业务开发使用新的 `/api/v2/catalog/*`，不重新接入已删除的旧前端模块。建议接口：

- `GET /api/v2/catalog/skus`：搜索、筛选、排序与分页。
- `GET /api/v2/catalog/skus/:id`：读取身份、编号、适配、证据与业务摘要。
- `POST /api/v2/catalog/intakes`：建立来源采集任务。
- `POST /api/v2/catalog/epc-previews`：保存 EPC 原始批次并生成写入前匹配预览。
- `POST /api/v2/catalog/epc-previews/:id/commit`：按版本锁写入明确选择的决定。
- `POST /api/v2/catalog/skus`：从采集结果或空白草稿创建 SKU。
- `PATCH /api/v2/catalog/skus/:id`：带版本号更新草稿。
- `POST /api/v2/catalog/skus/:id/verify`：完成核验。
- `GET /api/v2/catalog/skus/:id/changes`：读取变更历史。

旧 `/api/v1/skus` 在迁移期仅用于数据核对，不作为新页面直接依赖；迁移完成后再决定归档时间。
