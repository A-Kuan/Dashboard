# 架构说明

## 当前范围

方案 A：React + TypeScript + Vite，使用 React Router 提供浏览器端路由。

当前范围是基础骨架、参考图风格的左侧导航与独立报价模板模块。首页保留最小骨架；报价模块按照用户选定的 16:9 视觉图实现，支持持久化管理通用车型与配件组合、填写一次性报价草稿并复制文字。导航图标使用 @tabler/icons-react。已新增 Node.js + SQLite 后端、登录、客户档案和 SKU 管理，详见下文。

技术版本以 package.json 的精确版本和 package-lock.json 为准。

## 目录与职责

```text
src/
  App.tsx                 根组件与路由
  main.tsx                React 启动入口
  config/app.ts           公开应用配置
  config/navigation.ts    导航分区、分组与链接配置
  components/layout/      共享布局入口与承载布局样式
  components/navigation/  导航组件、类型与局部样式
  features/quotes/        报价模板、车型配件数据与局部样式
  pages/                  首页与 404 页面
  vite-env.d.ts           环境变量类型
docs/                     全局文档与视觉参考
.github/                  CI 与 PR 模板
```

## 路由

| 地址              | 页面     | 当前行为           |
| ----------------- | -------- | ------------------ |
| /                 | 首页     | 最小骨架就绪提示   |
| /quotes/templates | 报价模板 | 模板编辑和报价草稿 |
| 其他地址          | 404 页面 | 返回首页链接       |

共享布局包含 Sidebar 和主内容区域。Sidebar 从 config/navigation.ts 读取配置；按工作台、客户与报价、商品资料、系统设置分组。应用名称从 VITE_APP_NAME 读取，默认 Dashboard。

报价模板以车型、配件名称、品牌和可选备注组成通用条目，按可编辑的“常用模板”和“其他模板”分组，支持搜索、新建、编辑和删除。模板行右侧三点打开居中编辑弹窗，可修改名称、适用客户、模板备注和分组；模板内可增删车型配件。模板与配件保存在 SQLite 的 `quote_templates` 和 `quote_template_parts`，更新使用版本号防止覆盖，删除时级联移除配件。原前端示例不自动写入正式数据库，新数据库显示空状态。只有一次性报价草稿留在页面内存中，复制文字仍需人工核对；模板未自动关联客户、SKU、零件号、适配、库存或价格。

导航使用原生 button 折叠分组、NavLink 表达当前页面，并提供移动端菜单。展开状态仅保存在当前组件中，不持久化。样式与交互规范见 [NAVIGATION.md](NAVIGATION.md)。

部署时需配置 SPA 回退，使直接访问未来新增的子路径也能返回 index.html。前端 404 是页面展示，不会改变静态服务器返回的 HTTP 状态码。

## 后续扩展

页面负责组合，公共组件放在 components，业务逻辑在实际需要时建立 features/<模块>。多个页面使用相同选择项时应提取共享字典，避免各页面硬编码。

业务请求由 src/lib/api.ts 访问同源 /api，开发时 Vite 代理到 4182，构建后 Node 直接提供 dist 与 SPA 回退。前端隐藏入口不能替代服务端权限校验。

## 登录、客户和 SKU

- `/skus`：启用 SKU 列表、筛选、分页、新建、编辑及停用管理。库存零也显示，不含库存预警。
- `/customers`：客户项目看板，按跟进阶段分列、按客户类型筛选；保留客户编码、名称、联系人、电话、备注与启停编辑，右侧显示客户详情和可持久保存的跟进记录。
- `/settings/accounts`：管理员创建和启停账号，不能停用当前账号。
- `/settings/dictionaries` 与 `/sku-foundation`：分别展示配置中心字典和商品基础字典；管理员可维护可编辑分组的选项，固定分组只读。
- `src/features/auth`、`customers`、`catalog` 承载对应页面；`src/components/business` 提供共用表单、居中 dialog 和表格样式。
- `src/components/business/Select.tsx` 提供业务下拉列表的统一外观、选项搜索和键盘交互；所有引用该组件的筛选与表单下拉自动支持按名称或值搜索，页面不直接使用原生 select 弹出菜单。
- `src/features/dictionaries` 提供两套来源独立的字典页面、服务端分页、搜索与选项编辑。有父子关系的选项按父项排序分组，页面突出一级项并缩进显示子项；搜索单独命中子项时仍返回上级名称作为上下文。
- `server/app.mjs` 处理 API、会话和静态页面；database.mjs 建表，validation.mjs 校验；scripts/dev.mjs 启动前后端。
- shared/catalog.json 为前后端共用字典与缺省选项，定义旧供货性质编码的回退项、历史值、产地、分类、单位、件号类型及角色。

SQLite 默认保存在 `.data/dashboard.sqlite`，启用 WAL 与外键。users、sessions、customers、skus、sku_numbers、fitments、stock_balances、customer_prices、quote_templates、quote_template_parts、audit_log 分表保存。测试使用隔离临时数据库。

客户项目阶段保存在 `customers.project_stage`，旧数据升级时默认“待跟进”；`customer_activities` 保存客户跟进内容、作者与时间。客户类型和项目阶段由 `shared/catalog.json` 统一定义。客户项目目前未和报价模板或实际报价单建立关联，右侧报价区域显示空状态。

SKU 主数据包含编码、名称、品牌、分类、厂家件号、供货性质、产地属性（国产/进口/待确认）、生产国家地区、销售单位、规格、安装位置、包装数量、图片链接、备注与启用状态。供货性质使用旧站 `sku_foundation/supply_type` 的编码与父子层级，原厂件、品牌件、待核实及其子项均可选；“德国”和“进口大众”要求产地为进口。已有 SKU 的“待确认”等旧值保留并允许继续编辑，新建使用字典编码。列表将历史“待确认”显示为“待核实（旧值）”，`UNKNOWN` 筛选同时匹配两者。同件号不同供货性质或产地可建立不同 SKU。

一个 SKU 可对应多个关联件号、适配车型、仓库库位和客户价。适配含品牌、车系、代号、年款、动力、发动机与核对标记。库存是非负整数快照，不含出入库流水；未录入与零库存分别显示。客户价按 SKU + 客户唯一，以人民币分整数保存；未设置价格不等于零，也不使用其他客户价格。更新使用版本号防止并发覆盖，关联资料以事务一起保存。

所有业务 API 必须登录，管理员和编辑可维护客户/SKU，只读账号只能查看；管理员独占账号管理。密码以 scrypt 散列保存，会话令牌只存哈希；Cookie 使用 HttpOnly、SameSite=Strict，生产模式加 Secure。写请求校验 Origin 和自定义头，登录按来源 IP 限流；仅在明确开启并且直接连接来自回环地址时才读取 Nginx 覆写的 X-Real-IP。停用账号撤销会话，业务写入记录审计。

报价模板已持久保存，但尚未与客户、SKU、价格自动关联。SKU 列表通过 `/api/skus/page` 服务端分页（每页 20 条）、筛选和搜索；仅查询当前页的关联资料。

旧站数据通过 `scripts/import-legacy-skus.mjs` 从只读 NDJSON 快照导入。名称包含“弃用零件”的记录在导入时跳过。`sku_source` 记录来源系统、来源 ID、原分类路径、原厂家和完整原始记录，支持重复运行时按来源跳过。导入保留 OE/替代件号与车型适配；未能确定映射的品牌留空，配件性质和产地标为“待确认”。旧站价格快照保留在来源记录中，不自动映射为同行价、修理厂价或供应商报价；旧站没有库存记录，目标库存也保持未录入。源数据和数据库备份只放在忽略提交的 `.data` 内。

两套旧站字典通过 `scripts/import-legacy-dictionaries.mjs` 导入到 `dictionary_groups`、`dictionary_items`、`dictionary_logos`。来源 scope、编码、标签、说明、排序、状态、层级、原始 JSON 和品牌 Logo 均保留，重复导入不会覆盖本地维护。配置中心有 18 组，商品基础字典有 10 组。字典 API 均须登录；管理员可维护可编辑分组，固定分组及其他角色只读。SKU 新建和编辑使用商品基础字典中启用的商品品类、商品品牌、单位、供货性质、安装位置和适配汽车品牌；商品经营状态及适配核实状态的现有布尔字段也使用对应字典中的可表达状态。安装位置支持组合多个字典项。供货性质在列表中按编码显示对应中文标签；其他当前文本字段保存字典标签，以兼容已有数据结构。既有 SKU 的旧值可继续保存，已停用的字典项不再用于新建。货品状态仍是独立维度，未映射至供货性质；现有 SKU 结构尚未承载货品状态字典和资料来源类型。

## 价格与供应商报价

客户类型为同行、修理厂或待分类；旧客户升级时设为待分类，由用户逐个确认。SKU 分别维护同行价和修理厂价，可留空；原 customer_prices 保留为客户协议价。报价优先级为客户协议价、客户类型售价，缺价时明确显示未设置。金额以人民币分保存，零元与未设置有区别。

supplier_quotes 独立保存每次供应商报价，包含供应商、报价日期、人民币报价、备注与记录时间。新增记录不会覆盖历史，也不会自动修改客户售价。SKU 列表显示最近报价，快速报价弹窗展示适用售价、最近供应商报价及本次输入售价与供应商报价的差额。该差额不是实际利润。临时售价仅供本次复制文字，不写回 SKU 价格；客户收到的文本不含供应商报价。

旧数据库通过启动时的非破坏性列迁移新增客户类型、两档售价和供应商报价表，现有客户协议价、SKU、会话与账号保留。前后端共享价格字段；供应商报价新增由单独 API 写入并做角色校验和审计。
